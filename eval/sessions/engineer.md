# 会話テスト: engineer

利用者像: 懐疑的なソフトウェアエンジニア。メタな質問で入り、AI と仕事、LLM の限界、プログラミング、誤情報、SNS の話をする。言い換え、長文、直前を受けた追及を多めに混ぜた。
ターン数: 20（直前を受けた発話: 4, 5, 9, 11後の12, 14, 15, 19, 20 で 8 ターン）
記録: `eval/sessions/engineer.jsonl`

## 1. 集計

| ok | meh | ng |
|---|---|---|
| 7 | 3 | 10 |

ng の内訳: needless-fallback 5、context-break 4、wrong-intent 1。meh: awkward 2、context-break 1。

単発のメタ質問（中身、LLM の有無、人工無脳）はよく当たる。崩れるのは、(a) 直前の bot 発言を受けた追及、(b) 長文や言い換え、(c) 誤情報と SNS の話題、の3つ。

## 2. 重要な ng / meh

1. **T4「それってどういう意味？」** → 「その問いに答える文を、私は持っていません。」(play.fallback/6)
   play.llm/4（「細かいところは拾えません」）の直後。自分の説明を言い直す文脈ルールが無い。
2. **T5「細かいところを拾えないって、具体的には？」** → 「その言葉は辞書の外でした。…一貫性は…」(play.fallback/consistency)
   bot 自身の発言を引いた追及。play.llm の後の「具体的には？」を受ける例文が無い。
3. **T6「じゃあ文字のn-gramで近い文を探してるだけってこと？それって昔の人工無脳と同じじゃない？」** → 「正直に言うと、何を返せばいいのか分かりません。」(play.fallback/15)
   短く言った T7「人工無脳みたいなもん？」は play.heart/0 に 0.5 で当たる。長文になると self.bot/play.heart が 0.19 まで薄まる。「n-gram」「近い文を探してるだけ」も例文に無い。
4. **T9「たとえば？」**（info.ai_jobs/0「なくなるのは仕事というより、仕事の中の作業です」の直後） → エレベーターの観察 (play.fallback/elevator)
   bot が抽象的な主張をした直後の「たとえば？」に具体例を返す文脈意図が無い。
5. **T10「エンジニアとしては、コード書く作業がどんどんLLMに置き換わってる実感があるんだよね」** → 「受信はしましたが、解読できませんでした。」(play.fallback/7)
   info.programming 0.22。「AI でコーディングが置き換わる」という意図が無い。info.ai_jobs と info.programming の間に落ちている。
6. **T13→T14→T15（ハルシネーション）**
   - T13「LLMってよく平気で嘘つくじゃん…直らないと思う？」 → info.ai_mistakes/1「AIを捨てるのは…同僚を全員解雇するようなもの」（meh: 「直るか」に答えず、言っていない「捨てる」に反論）
   - T14「いや捨てろとは言ってないけど。同僚の嘘とAIの嘘は違くない？」 → 素数の話 (play.fallback/primes)
   - T15「話そらしたね」 → play.change_topic/2「わかりました、ここからはクイズでも…そちらへ移ります」（wrong-intent: はぐらかしの指摘を話題変更の依頼と取った）
   懐疑的な利用者には、この3連続がいちばん印象を悪くする。
7. **T16「SNSでデマが広がるのってどうしたら止められると思う？」/ T17「デマってなんで広がるの？」** → どちらも fallback
   info.misinformation がそれぞれ 0.178、0.251 で閾値未満。「フェイクニュース」と言った T18 だけ canonical:110 に 1.0 で当たる。「デマ」「誤情報」「嘘の情報」「拡散」の例文が足りない。
8. **T19「…SNSのタイムラインってそもそも考える暇を与えない設計じゃない？」** → 猫の話 (play.fallback/cat)。**T20「猫は好きだけど。SNSは使ってて疲れる」** → self.animals/2
   info.sns 0.265 で落ちる。続く T20 では、fallback/cat の問いへの答えを play.fb_cat_yes (0.2) で受けられず self.animals に取られた。SNS 疲れも拾えていない。

## 3. 追加すべき意図・例文の提案

- **play.llm / play.how_works / play.whats_inside の後の追及（文脈つき）**
  「それってどういう意味？」「具体的には？」「細かいところって？」を受けて、具体例で言い直す。
  例文の返答案: 「たとえば『猫が好き』と『猫は嫌いじゃない』は、私には近い文に見えます。否定や皮肉の細かい違いは、取りこぼします。」
- **play.how_works の言い換え例文**
  「n-gramで近い文探してるだけ？」「類似度で選んでるの？」「検索してるだけじゃん」「昔の人工無脳と同じ？」「ELIZAみたいなもの？」を play.how_works か play.heart に入れる。長文でも当たるよう、キーワード（n-gram、類似度、人工無脳、ELIZA）を含む例文を増やす。
- **info.ai_jobs の後の「たとえば？」（文脈つき）**
  返答案: 「翻訳なら、訳文を作る作業は減り、何を訳すかを決める仕事が残ります。」
  info.* 系で抽象的な主張をした返答全般に、「たとえば？」「具体的には？」「なんで？」の文脈意図を付けるのがよい（T4、T5、T9 は同じ穴）。
- **info.ai_coding（新規）** 「AIでコード書くのが置き換わってる」「Copilotで仕事が変わった」「プログラマーは要らなくなる？」「この先も人間がプログラミングする意味ある？」
  返答案: 「コードを書く作業は減ります。何を作るべきかを決める部分は、まだ HS の側に残っています。」T11 の info.programming/ask（言語を尋ね返す）もこちらへ回す。
- **info.hallucination（新規、または info.ai_mistakes の分割）** 「ハルシネーション」「AIが平気で嘘つく」「直らないの？」
  返答案: 「次に来そうな語を選ぶ仕組みである限り、もっともらしい誤りはゼロになりません。減らすことと、確かめる手順を持つことはできます。」
  info.ai_mistakes/1（「捨てるのは解雇と同じ」）は、利用者が「AIを使わない」と言ったときだけ出るように絞る。
- **info.ai_mistakes の後の反論（文脈つき）** 「人の嘘とAIの嘘は違う」「捨てろとは言ってない」
  返答案: 「違います。人の嘘には意図があり、AI の誤りには意図がありません。だから責める先ではなく、確かめる仕組みが要ります。」
- **daily.dodged（新規）** 「話そらしたね」「はぐらかした」「ごまかしたでしょ」
  play.change_topic と分ける。返答案: 「はい、そらしました。答える文を持っていなかったので。」（ルールベースの正直さが人格に合う）
- **info.misinformation の例文追加** 「デマ」「誤情報」「嘘の情報が拡散」「デマはなぜ広がる」「どうしたら止められる」。canonical:110 に頼らず意図側で受けられるようにする。
- **info.sns の例文追加** 「タイムラインは考える暇を与えない」「SNS疲れる」「アルゴリズムが怒りを増幅する」「SNSやめたい」
- **canonical:110 の後の反論（文脈つき）** 「批判的に考えろって言うのは簡単」「それは理想論」
  返答案: 「その通りです。個人に頼るより、広がる速さを落とす設計の方が効きます。」
- **play.fallback/cat の後の答え** 「猫は好きだけど、…」のように答えに続く文があると、fb_cat_yes が self.animals に負ける。文脈つき意図の重みを上げるか、「猫は好きだけど」「好きだよ」で始まる例文を fb_cat_yes に入れる。
