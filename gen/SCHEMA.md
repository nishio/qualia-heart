# ルールファイルの書式

生成物は `gen/out/<topic>.json`（UTF-8、JSON。コメント不可）。`tools/build.mjs` が全ファイルを検証・結合して
`docs/pack/qualia.json` を作る。エンジンは `docs/engine.js`。

## 照合の仕組み（書く前に知っておくこと）

- 入力は正規化（NFKC、小文字化、カタカナ→ひらがな、記号と空白の除去）してから、
  **各意図の `examples` と文字 2-gram/3-gram の TF-IDF コサイン類似度**で比べる。意図の得点は最も近い例文の値。
- 正規表現ではなく「例文との近さ」で当たる。**だから例文の多様さが網羅性のすべて**。
  同じ意図を、敬体・常体・くだけた口語・一語だけ・長めの文・ひらがな書き・よくある言い換えで書く。
  例文同士がほぼ同じ文字列なのは無駄。
- 他の意図の例文と紛らわしい例文は誤爆の原因になる。意図の中心から外れる例文は入れない。
- 得点が閾値未満なら正典検索、それも外れたらフォールバック（topic を振る返答）になる。

## トップレベル

```json
{
  "topic": "daily",
  "intents": [ ... ],
  "fallback": [ ... ]        // 任意。どれにも当たらないときの返答（Response の配列）
}
```

## Intent

| フィールド | 必須 | 内容 |
|---|---|---|
| `id` | ○ | `<topic>.<slug>`。英小文字・数字・`_`・`-`。ファイル内で一意 |
| `examples` | ○ | ユーザー発話の例。通常の意図は **15〜30個**、文脈つき意図は 6〜15個 |
| `responses` | ○ | Response の配列。通常 **4〜8個**、文脈つきは 2〜4個 |
| `context` | | この意図が「直前の bot 発言への返し」であるとき、その発言の参照（下記）。指定すると、**直前の bot 発言がそれに該当するときだけ**照合される（得点にも加点） |
| `pattern` | | JavaScript 正規表現のソース（フラグなし）。NFKC 済み・小文字化済みの**生の入力**に対して試す。当たれば例文得点より優先。名前付きグループ `(?<name>...)` は記憶に保存される。名前の取得など、例文照合で拾えないものだけに使う。pattern だけで当てたい意図は `examples: []` にする。取り出した値は、その入力への返答を選ぶ時点で `requires` に効く |
| `priority` | | 数値、既定 0。同点付近で具体的な意図を勝たせたいとき 0.05〜0.1。類似度 0.3 未満では効かない |
| `more` | | Response の配列（1〜3個）。この意図の返答の直後に、汎用の聞き返し（「なんで？」「たとえば？」「どういうこと？」「もっと詳しく」）が来たときに使う補足。下記 |

### 補足 `more`

汎用の聞き返しは `generic.json` の意図（`followup: true`）が受け、**直前の意図の `more` から未使用のものを返す**。
`more` が尽きると generic の汎用文になる。だから `more` は「この意図について、理由・具体例・言い直しを
一段深く述べる文」にする。直前にどの返答が出たかは分からないので、**どの返答の後でも成り立つ**ように書く。
返答に比喩を使ったら、その比喩を平たく言い直す `more` を必ず用意する。
特定の返答の後で特定の返しを受けたいなら、従来どおり文脈つき意図を書く（そちらが優先される）。

### 文脈つき意図（Heart のデータファイル A に相当）

bot が質問や話題振りで終わる返答を書いたら、**その返答への典型的な返し**を文脈つき意図として書く。
例：返答「あなたは朝型ですか、夜型ですか。」→ 文脈つき意図「朝型」「夜型」「どちらでもない」。
「なんで？」「たとえば？」「本当に？」「へえ」「わかる」「違うと思う」のような汎用の返しも、
重要な返答には文脈つきで書くと会話が続く。

`context` の値は文字列の配列で、各要素は
- `"<intent id>"` … その意図のどの返答の後でもよい
- `"<intent id>/<response id>"` … その返答の後だけ
- `"<topic>.fallback"` / `"<topic>.fallback/<response id>"` … そのファイルのフォールバック返答の後

## Response

| フィールド | 必須 | 内容 |
|---|---|---|
| `text` | ○ | 返答文。テンプレート `{name\|あなた}` は記憶 `name` があればその値、なければ `あなた` |
| `id` | | 短い英小文字の slug。`context` から参照するときだけ必要 |
| `next` | | 意図 id の配列。この返答の後、それらの意図を少し当たりやすくする（話題の継続） |
| `requires` | | 記憶キーの配列。全部あるときだけ選ばれる |
| `set` | | 記憶への代入 `{"key": "value"}`。値にも `{...}` テンプレートが使える |

同じ意図の返答は、エンジンが**直近に使ったものを避けて**ランダムに選ぶ。

## 正典インデックス（`topic: "canon-index"` のファイルだけ）

```json
{
  "topic": "canon-index",
  "canon": [
    {
      "id": "canonical:001",
      "examples": ["GPT-4 についてどう思う？", "..."],   // この正典が答えとして自然な問い・話題 5〜10個
      "lead": "",                                     // 任意。引用の前に置く短い一言（クオリアさんの声で）
      "quote": "..."                                   // 返答に使う部分。canon の text から**逐語で抜き出す**（Q: の部分、A: の記号、(1/2) は除く）
    }
  ]
}
```

`quote` は build 時に正典本文の部分文字列であることを検査する（正規化後）。言い換えは不可。

## 記憶キーの約束

- `name` … ユーザーの呼び名
- 他に使うキーは短い英小文字で、ファイル冒頭の `"memoryKeys": {"key": "説明"}` に書く（任意フィールド）。

## 品質の目安

- 1つの意図の返答の長さを混ぜる（1文を必ず1つ以上）。
- 質問で終わる返答は全体の2割以下。
- 返答はどの文脈で出ても破綻しないように（`gen/PERSONA.md` 末尾）。
